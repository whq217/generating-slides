# 焦点与强调判断规则（视觉焦点前置）

> 日期：2026-10-22 收敛版 ｜ 来源：维护者 10-21/10-22 两日授课全量
> 定位：**焦点识别之后、排版执行之中的判断层**——content-optimization §3.7 管"选谁当焦点、选什么布局"，本文档管"焦点定档之后怎么强调、强调的度和红线"；排版工程约束走 [layout-rules-v2.md](layout-rules-v2.md)。本文件只留现行规则。
> 标注：【经验】= 维护者判断 ｜【验证】= 落地稿复盘验证

---

## 总纲

```
手法层（尺寸/颜色/容器/留白/线/时序）→ 会被风格淘汰
原则层（CRAP：对比/重复/对齐/亲密性）  → 跨风格恒定
判断层（本文件主体）                  → 分寸所在，水平差距所在
```

**焦点是通过对比成立的"关系"，不是"放一个很大的东西"**——手法是答案，层级判断才是问题。

决策流三步：**定焦点（谁）→ 选手法（怎么）→ 守纪律（几分）**。

---

## 一、定焦点：层级三问

每页排版前依次回答：

1. **观众只能记住一个数/一句话，是哪个？** → 主焦点（唯一）
2. **第二眼落在哪？要不要凸显？** → 次级焦点（此刻才轮到手法选择）
3. **剩下的是什么？** → 背景层，保持平、不许抢（来源/口径/页码天生该灰该小）

**焦点服从论述意图，不服从数字大小**——数字大 ≠ 该当焦点，"这页论点靠哪个数站着"才决定。

**层级三问是递归的**：页面 → 焦点组 → 焦点元素，每层内部再分主次、再做对比——大数字组是页面焦点（其余墨色退后），组内数字与单位再来一层（数字红+大，单位灰+正文档）——层层对比成**错落感**，不是两极硬切。【验证：15.97 红巨数+灰单位 vs 墨色正文】

- **立场决定强调对象**："我是谁"是论述意图的一部分（甲方强调自己那一方，哪怕对手的绝对数字更大）
- **焦点成梯度，禁只有两档**：176 → 92 → 24 三级阶梯，页面要有第二落点
- **单焦点页型**：金句/焦点数字/封面 = 一页一个主角，全版面配额给一个元素，禁第二焦点；留白配主角红线（28px/25%=空版负样本）→ 真源 layout-rules §1.4
- **多级强调配级**：手法重量配优先级（第一优先行级浅色块、第二优先单元格级），禁倒挂；范围大小天然编码优先级（整行 > 整列 > 单格）；**撞色警告**——立场强调 vs 数据语义色（红=跌）撞车时：底色给立场、字色给语义

## 二、选手法：两轴对比 + 结构辅助

判断焦点成不成立，先问两条轴各占住了没有，再考虑结构辅助。

### 色轴 · 三层律

1. **明度反向律（通用基线）**：深底浅字、浅底深字——可读第一律，先过这条再谈其他。SVG 文本不吃继承，必须显式 fill（深底上默认黑字=隐形地雷）
2. **主色制（deck 级）**：一 deck 一主色，**主色即强调色**，与基调色构成根本对比对；禁第二强调色
3. **最大数字吃主色 = 默认基础手法**：hero 大数字吃主色（红黑对比是基本形式），前提=主色有明确身份（品牌色/既定强调色）。配级随之成型：主数字主色 / 次级数字墨 / 正文灰。语义撞车只在同层级同尺寸场景成立（表格格子级）；hero 级的强调语义与数据语义不混淆。全 deck 一致执行是重复原则的运用（"红巨数=本页核心"的阅读惯性），不是配额通胀

### 量轴 · 三条

1. **悬殊才有效**：7.3:1 的差距才叫对比，小幅差距=没差【验证：176 vs 24】
2. **周围退档**：焦点周围元素（单位、说明）全部退到**统一背景档**——单位=正文字号，禁中间尺寸（49px 的单位是对比的稀释剂：巨数旁边带个"一大一小并列"感）【验证：15.97 的"万亿元"】
3. **强调是差不是量**：把一个东西放大是强调，把周围一起放大是重量分散——平均字号膨胀=页沉=失焦；**孤峰才有焦点，丘陵没有**

留白是量轴的极端形态：留白不是"空着"，是减法强调的极致——主角放大到仪式位 → 次要按亲密原则缩小归堆（贴边/压灰/小字）→ 焦点四周留隔离带（主角侧最大）。

### 捕获力排序

```
动画 > 图像/色块/图表 > 图标 > 文字（文字内：大数字 > 短句 > 长段）
```

- **捕获力排序必须服从层级排序**：动画/色块挂在次级元素上=眼球被劫持=层级倒挂
- **捕获力越高，配额越严**：动画第一捕获器→三层收敛默认克制档；图标>文字→版率不足禁加图标
- 特例：人物面部（直视镜头）≈动画级配额

### 结构辅助

**容器（卡片）**——**层级判定前置（2026-10-22 维护者补，第一问）**：这组内容是同层级还是上下层级？
- **同层级**（多组内容无优先权、无主从；步骤/流程有先后序列但仍平级——序列管先后，层级管主从，两轴正交）→ 才可进下方四场景判定
- **上下层级**（核心解释在上+论证在下、主张+论据、结论+支撑、**数字是对图表的提炼重点**——数字上位/图表下位，包容解释关系）→ **禁多卡分组**：两卡分列=把主从错写成并列，容器改写语义。走主从形态（主从二式 / hero-split）

**四场景穷举**（2026-10-22 判定链收敛；默认无盒，出卡必须自证属于其一，说不出=撤盒）：

| # | 场景 | 例 | 卡在这里的作用 | 配额 |
|---|---|---|---|---|
| 1 | 身份独立的并列块 | 三方观点（甲说/乙说/丙说）、三个产品各自简介 | 给"这是 N 个独立东西"的信号 | ≤3 张/页 |
| 2 | 引用/证言切出 | 一段话要从正文流里单独成立 | 盒=切出标记 | 按需 |
| 3 | 选择性突出 | 五条建议里压重音的那一条 | 盒=重音 | **全局 1-3 次，稀缺才有效** |
| 4 | 异构视觉单元并列 | 柱形图+折线图 / 多图表组合 / 多卡位图墙。**禁：单数字+单图表组合**（2026-10-22 维护者校正）——数字与图表同页是**包容解释关系**（一组内容：数字是图表的提炼、图表是数字的展开），两张卡分列=把主从关系错写成并列关系，**容器改写了语义**（且卡内数字基线与图表基线两套对齐必不统一）→ 这类走 `hero-split`（数字主位+发丝线分栏图表副位，主从结构对号入座，无盒） | 规整对齐：卡锁等宽等高、统一起点与内边距（异构单元基线不一的治法，对齐责任从内容转移到容器） | 按需 |

- **默认无盒禁令（举证反转）**：文字默认行组/发丝线组/裸排起手（判定链 → layout-rules §3.1）；卡不是容器选项，是需要理由的例外
- **选择性突出两式（2026-10-22 维护者补，场景 3 的手法展开）**：①**有卡 vs 无卡**——同层级组内只给重音块加卡，其余裸排/行组；②**主色卡 vs 中性卡**——卡组内强调的那张走 accent（`.card` 默认），其余卡中性无色（`.card.mute`：顶线 hairline、数字 ink）。组内只许一张主色卡（强调效力=使用密度的倒数）。层级前提不变：这是同层级内部的强调选择，不改变"同层级才可多卡"的判定
- **数据绝大多数不用卡**：单个关键数字 → 焦点数字槽裸排（数字本身就是锚，加盒压主角）/ 2-4 指标并列 → metric 发丝线组 / 数据带论据展开 → 行组——只有"身份独立并列块"才走到卡（SKILL 判定树同口径）
- **全有等于没有**：禁全 deck 卡片化（dashboard 终局=零焦点）。**同构化优先**：内容能改相同结构→基线自然对齐，卡片没活干
- **最差用法（禁）**：长文字段落塞卡——卡是"并列选择"信号不是文字容器；大段字进卡像对话框，卡底参差破坏平衡律（两翼墨迹高度比 0.5-1 的防线管的就是它）
- **衬底双功能**：图上 badge/标签级小字 → **实色圆角小块**（非半透明）：①抗噪保可读 ②视觉引导——引导的本质=**纯色版图标**（色块与图标同为视线锚点，图上已有大量形象时用纯色块防打架）。**分档**：小面积用实色、大面积用半透明（防"膏药感"）——**衬底面积越大越要透**；尺寸纪律=刚好包住（砝码配层级）。图上边注：加深文字色或小衬底二选一；整页图上大文字走 image-handling（整页遮罩+白字）

**卡形态（确实用卡时——frontend-slides 蒸馏 R1/R2/R3，2026-10-22 落底盘 `.card` 组件）**：
- **R1 顶线卡 = 默认形态**：`border-top: 2px` accent + 无底色无盒（线档组标识）；盒装 `.card-box`（边框+轻底）仅品牌风格预设点名使用
- **R2 数据卡三段式**：`.card-num`（accent 大数字，主角）→ `.card-label`（标签贴身，正文档）→ `.card-note`（meta 档小注：口径/来源）；多卡并列锁等宽等高用 `.card-row`；单数字+单图表组合禁卡，走 `hero-split`（场景 4 校正）
- **R3 双面卡色律**：强调色引用 `var(--accent)`，随所在明/暗面自动翻转，不引入新色

**线与面**：线切分反衬块面分量；线的两种身份（引导线贴组内/分隔线组间）→ layout-rules §3.2

**时序（--d 编排）**：先入场的先被看到——排焦点顺序【验证：hero 240ms → metric 560ms+】

**动态两件**（step 家族，禁同页混用）：

- **依次揭示（`.step`）**=内容逐个出现，**硬拦截**（内容隐藏，没亮完不许走）——论述点逐抛、结论压轴
- **聚光（`.spot-group`，按需件）**=全组可见、当前项亮其余退后——**软拦截**（末项聚光后即放行，动画服务讲述不绑架讲述）；单点模式 `data-spot="1"`；**客户明确要求才配，生成端禁自动添加**（推断不出讲述意图）；组直接子项禁挂 `.rv`；print/编辑态自动全亮

## 三、守纪律：重量守恒与配额

### 视觉重量守恒

焦点设计=**重量的分配，不是堆叠**。每个手法都是砝码：尺寸/浓黑/色块（重）/饱和色；压灰/缩小/延迟=负砝码。

- **红线①：已是视觉最重的元素（hero 大数字）禁垫色块、禁再加码**——手法冗余（尺寸差已定焦点归属）+天平翻倒（7:3 正确失衡变 9:1 结构失稳）+图底吃字形（衬线数字的墨感被块面毁掉）
- **对称规则**：轻的内容要强调 → 可以加重量（浅底容器）；重的内容要再强调 → 禁加码，只准换维度（颜色/时序）或做减法（把周围压更灰更小更晚）
- **强调=搬运重量，不是凭空增重**——最优强调常是减法（压别人）
- **两翼墨迹对等**：左右结构平衡的对等单位是**墨迹面积**（大而稀的巨数 ≈ 小而密的多行正文），不是字号不是元素数。焦点讲顺序（尺寸梯度），平衡讲稳定（墨迹对等）——两套并行，面积对等与主次分明同时成立【验证：hero-split】

### 稀缺配额

**强调手段的效力 = 使用密度的倒数**。红/动画/卡片同律：配额防的是**乱撒**（到处红点、每页装饰块），不是有纪律地给主焦点。真正撞车在同层级同尺寸（§一撞色警告）。

### 颜色系统查重

用色前先查该色在本系统的既有语义（分类色/警示/强调词）——一色多职时新增用途要过撞色检查。

### 对比靠减法

- **禁跨形态替换**：大标题方色块+小标题椭圆色块=用形态差异冒充层级对比，加观众解码负担；层级差异必须在同一语言内表达（有/无、粗/细、深/浅、大/小）
- **装饰词汇表 ≤1**：页面装饰种类最多一种，层级靠档位不靠形态——token 制度的深层理由：同一维度分档，禁临时发明新词汇（字号/间距只取档位白名单，发明新档=违规）

## 四、CRAP 对号（速查）

| 原则 | 对应 | 实证 |
|---|---|---|
| 对比 | 两轴三层律+量轴三条 | 176/24、红巨数 |
| 重复 | 主色制/固定件位置恒定/hero 吃主色全片一致 | kicker/folio/punch |
| 对齐 | 卡片规整/同构化/两翼墨迹对等 | duo 对称、seg-row 基线 |
| 亲密性 | **间距=关系强度的投影，按亲疏递进拉开**（强关联最小→中→弱最大，非平均分布）；组内=小而有缝，亲近≠贴上去（padding 呼吸永远保留） | stack 紧凑、legend 拉开 |
